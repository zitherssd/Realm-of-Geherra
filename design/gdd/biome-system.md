# Biome System

> **Status**: In Design
> **Author**: Developer + AI agents
> **Last Updated**: 2026-07-25
> **Implements Pillar**: Preparation Over Reflexes, Discovery-Driven Exploration

## Overview

The Biome System defines the properties of each terrain biome type in the game world. It is a data-driven lookup system: given a position (x, y) on the world map, it returns the biome at that location (using the Voronoi seed points generated by the Procedural World Generation system), and provides that biome's traversal speed modifier, visual palette reference, encounter tables, and special rules. The system is purely a data provider — it stores biome definitions and handles queries, but does not manage transitions or rendering directly.

## Player Fantasy

Biomes are what make travel meaningful. The player *feels* the difference between sprinting across open plains and trudging through a wasteland. They learn that forests offer cover but slower progress, that deserts are punishing but hide rare resources. The biome system rewards route planning — the core pillar of *Preparation Over Reflexes* — by making the choice of path a real tactical decision.

## Detailed Design

### Core Rules

1. **Data-driven definitions**: All biome properties are defined in `data/biomes.lua`. Each biome is a table with the following fields:
   ```lua
   {
       id = "plains",
       name = "Plains",
       traversal_speed_modifier = 1.0,  -- multiplier on base party speed
       visibility_modifier = 1.0,       -- how far the player can see (1.0 = baseline)
       encounter_frequency = 0.3,       -- 0.0–1.0 chance per time unit
       encounter_table = {"bandits", "wolves"},
       color_palette_ref = "plains",    -- references art bible §4.3
       ambient_audio_id = "ambient_plains",
       -- Rivers are impassable except at bridges/fords. No crossing penalty field needed.
       resources = {"herbs", "stone"},  -- gatherable resources
   }
   ```

2. **Biome query**: `BiomeSystem.get_biome(x, y)` → biome_id. Uses the Voronoi seed data from World Generation. Finds the nearest seed point to (x, y) and returns its assigned biome.

3. **Traversal speed**: Base party movement speed is multiplied by the biome's `traversal_speed_modifier`. Higher = faster. Road travel ignores the biome modifier and uses a separate road speed multiplier.

4. **Visibility**: Each biome has a visibility modifier that affects how far the player can see (used for party spotting and POI discovery). Lower visibility means parties and POIs are spotted at closer range.

5. **Encounter tables**: Each biome defines an encounter table — a weighted list of enemy party types that can appear when an encounter is rolled. The `encounter_frequency` value determines how often encounter rolls happen while travelling in that biome.

6. **Biome transitions**: When the player moves between biomes, the transition is smooth — speed, visibility, and ambient audio lerp over a ~2-second blend period. Encounter tables switch immediately at the boundary.

### Biome Definitions

| Biome | Traversal Speed | Visibility | Encounter Freq | Encounter Table |
|-------|----------------|------------|----------------|-----------------|
| Plains | 1.0 (baseline) | 1.0 (far) | 0.2 (rare) | Bandits, wolves |
| Forest | 0.7 | 0.5 (limited) | 0.5 (frequent) | Bandits, wolves, bears, wild boar |
| Hills | 0.8 | 1.3 (far + high ground) | 0.3 | Bandits, mountain goats (rare) |
| Wasteland | 0.5 | 0.8 | 0.6 (frequent) | Giant scorpions, undead, desperate bandits |
| Desert | 0.7 | 1.0 | 0.4 | Giant scorpions, nomads, sand beasts |
| Snow Forest | 0.5 | 0.4 (limited) | 0.4 | Wolves, yeti-like creatures, frost trolls |
| Snow Plains | 0.8 | 1.2 (far + flat) | 0.2 | Wolves, frost trolls |
| Beach | 1.0 | 1.0 | 0.1 (very rare) | Coastal creatures (crabs, minor threats) |
| River (crossing) | — | — | Special | — |

### States and Transitions

| State | Description |
|-------|-------------|
| **Ready** | Biome definitions loaded. Queries return immediately. |
| **Transitioning** | Player is between biomes. Speed/visibility/audio values are lerping. Duration: ~2 seconds. |

### Interactions with Other Systems

| System | Direction | Interface |
|--------|-----------|-----------|
| World Generation | Consumes (Voronoi seeds) | `world_data.biomes.seeds` — array of seed points with biome assignments |
| World Map Navigation | Provides | `get_traversal_modifier(x, y)` → speed multiplier |
| Party Encounter System | Provides | `get_encounter_table(biome_id)` → weighted enemy list. `get_encounter_frequency(biome_id)` → float |
| Map/Minimap System | Provides | `get_biome_at(x, y)` → biome_id for colouring the map |
| Audio/Music System | Provides | `get_ambient_audio(biome_id)` → ambient sound ID |
| POI System | Provides | `get_biome_at(x, y)` → biome_id for context-appropriate POI spawning |

## Formulas

**Traversal speed at position (x, y):**

`speed(x, y) = base_speed * biome.traversal_speed_modifier * (is_road(x, y) ? road_speed_multiplier : 1.0)`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| Base party speed | `base_speed` | float | 50–200 | Party's base movement units/sec |
| Biome modifier | `traversal_speed_modifier` | float | 0.3–1.5 | Per-biome speed multiplier |
| Road multiplier | `road_speed_multiplier` | float | 1.5 | Bonus speed on roads |

**Example:** Party with base speed 100 in a forest (0.7): `100 * 0.7 = 70` units/sec. On a Mycenaean paved road through the forest: `100 * 1.5 = 150` units/sec.

## Edge Cases

- **If biome data at (x, y) is outside the map bounds**: Return the nearest edge biome. The world generation system ensures the entire walkable area is covered by Voronoi cells.
- **If the encounter table is empty**: `encounter_frequency` is treated as 0. No encounters roll in that biome (but parties from neighbouring biomes may wander in).
- **If the biome definition is missing a field**: Log a warning and use defaults (speed=1.0, visibility=1.0, frequency=0.0). The system should never crash from a missing biome field.
- **If the player crosses a biome boundary every frame (jittering)**: The transition lerp uses a hysteresis buffer — the system tracks "current biome" and only triggers a transition event when the biome at the player's position has been stable for 0.5 seconds.
- **At 800×600 resolution**: Biome data is resolution-independent. No changes needed.

## Tuning Knobs

- **Traversal speed modifier per biome**: Float 0.3–1.5. Adjustable in `data/biomes.lua`.
- **Visibility modifier per biome**: Float 0.3–2.0. Adjustable in `data/biomes.lua`.
- **Encounter frequency per biome**: Float 0.0–1.0. Adjustable in `data/biomes.lua`.
- **Encounter table weights**: Integer per entry. Higher = more likely. Adjustable in `data/biomes.lua`.
- **Transition blend duration**: Float seconds. Default: 2.0. Range: 0.5–5.0.
- **Road speed multiplier**: Float. Default: 1.5. Range: 1.0–3.0.
- **Biome hysteresis duration**: Float seconds. Default: 0.5. Range: 0.1–2.0.

## Visual/Audio Requirements

- **Visual palette**: Each biome references a per-biome color rule from the art bible (§4.3). The Map/Minimap system uses these colours to render the world map.
- **Audio**: Each biome has an ambient audio ID. The Audio/Music System plays the appropriate ambient loop when the player enters that biome, crossfading on transitions (see S03 Audio/Music System).

## UI Requirements

- **No direct UI.** The current biome may be displayed as an indicator on the HUD (e.g., text label "Forest" or a small icon). That UI belongs to the HUD system, not the Biome System.
- **Tooltip data**: If the player hovers over the world map, a tooltip could show the biome name at that position. Data provided by `get_biome_at(x, y)`.

## Acceptance Criteria

- **GIVEN** a position (x, y) on the world map, **WHEN** `BiomeSystem.get_biome(x, y)` is called, **THEN** it returns a valid biome ID.
- **GIVEN** the player enters a forest biome, **WHEN** speed is queried, **THEN** it is 70% of the plains speed.
- **GIVEN** the player is on a road in a forest, **WHEN** speed is queried, **THEN** it uses the road multiplier, not the forest modifier.
- **GIVEN** a desert biome, **WHEN** encounter frequency is queried, **THEN** it returns the desert's configured value.
- **GIVEN** a biome definition is missing `traversal_speed_modifier`, **WHEN** the biome is queried, **THEN** a warning is logged and the default (1.0) is used.
- **GIVEN** the player is near a biome boundary, **WHEN** the biome at their position flickers, **THEN** the system does not trigger rapid transitions (hysteresis prevents jitter).
- **GIVEN** all biome definitions in `data/biomes.lua` are loaded, **WHEN** the game starts, **THEN** all 9 biomes (7 land + river + beach) are available for queries.

## Open Questions

- **River biome**: Rivers aren't a biome in the Voronoi sense — they're splines overlaid on the terrain. Should the Biome System handle river queries separately (e.g., `is_river(x, y)`), or should rivers be treated as a special biome type? Proposed: separate `is_river(x, y)` query handled by World Generation data.
- **Biome-specific resources**: Should certain biomes have exclusive gatherable resources (e.g., herbs in forests, gems in wastelands)? Proposed: add a `resources` field to biome definitions for future crafting/economy systems. Not critical for MVP.
